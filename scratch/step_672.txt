## Voice Pipeline Root-Cause Audit Report

---

### ROOT CAUSE AUDIT & ANALYSIS

The investigation reveals that the voice agent's failure to understand speech, repetition of messages, and incorrect responses was caused by **G. A combination of the above** factors across the STT, TurnManager, session state, and WebSocket layers:

1. **Microphone Feedback Bleed During Assistant Playback (STT / Input Problem — A & C)**:
   - **Mechanism**: When assistant audio plays over laptop/desktop speakers, the microphone records the speaker output. Because microphone frames were continuously transmitted to AssemblyAI STT during playback without acoustic echo suppression, AssemblyAI transcribed the assistant's own voice and emitted it as an `STT FINAL` event.
   - **Result**: The assistant's own prior words were committed as the next user input (`"previous assistant response becomes the next user input"`), causing the assistant to respond to itself and endlessly loop or repeat previous messages.

2. **Barge-In Desynchronization Leaving TurnManager in `SPEAKING` State (Turn Lifecycle Problem — A & D)**:
   - **Mechanism**: When barge-in was executed (`_execute_barge_in` in [`orchestrator.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/orchestrator/orchestrator.py)), active LLM and TTS tasks were cancelled and pacer queues flushed, but `self.turn_manager.set_state(TurnState.LISTENING)` was never invoked.
   - **Result**: `turn_manager.state` remained trapped in `TurnState.SPEAKING`. When the user spoke next, [`turn_manager.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/orchestrator/turn_manager.py) rejected the finalized transcript at line 157 (`if self.state not in (TurnState.LISTENING, TurnState.BARGED_IN): return False`), logging `TURN DUPLICATE IGNORED` and discarding legitimate user speech.

3. **Overly Aggressive Substring Deduplication Dropping Follow-Up Turns (TurnManager Problem — A)**:
   - **Mechanism**: [`turn_manager.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/orchestrator/turn_manager.py) lines 138–154 rejected any utterance arriving within 4.0 seconds if `norm_new in norm_last and len(norm_new) >= 4` or if word overlap exceeded 70%.
   - **Result**: Valid follow-ups (e.g., *"Which one is the cheapest?"* vs *"How much does it cost?"*, or *"Book that one."* vs *"How much is my booking?"*) share common words (*"how"*, *"much"*, *"one"*) and were falsely dropped as `TURN DUPLICATE IGNORED`.

4. **Single Check-Out Date Overwriting Check-In Date (Session State Date Parser — E & B)**:
   - **Mechanism**: In [`session.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/orchestrator/session.py) line 90, when the agent had already registered `check_in = "2026-11-21"` and the user responded with a single date (e.g. *"November twenty sixth"*), the logic set `self.check_in = ci` instead of `self.check_out = ci`. Additionally, [`date_parser.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/utils/date_parser.py) lacked spoken number word normalization for words like *"twenty first"*, causing dates to fail parsing entirely.
   - **Result**: The agent lost the check-in date or failed to set check-out, repeatedly asking: *"What check-in and check-out dates are you planning?"*.

5. **Duplicate Sentence-Chunk Transcript Emission (Duplicate WebSocket Event — D)**:
   - **Mechanism**: In [`browser_websocket.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/telephony/browser_websocket.py), `BrowserOutboundPacer._pacing_loop()` broadcasted an assistant `{"event": "transcript", "role": "assistant", "is_final": True}` event for every sentence chunk, while [`orchestrator.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/orchestrator/orchestrator.py) concurrently broadcasted the full response via `event_broadcaster.notify_agent_response()`.
   - **Result**: Duplicate assistant messages were rendered on the frontend.

6. **PostgreSQL Offline Connection Refusal in Availability Check (Database Fallback — B & F)**:
   - **Mechanism**: When PostgreSQL is offline, [`check_availability()`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/tools/availability.py) threw `[WinError 1225]` and returned `available_rooms: []`, unlike [`pricing.py`](file:///c:/Users/Bhavyasree/Desktop/voice%20agent/app/tools/pricing.py) which has a static catalog fallback (`RESORT_ROOMS`).
   - **Result**: Empty available rooms in the session prevented the LLM from comparing rooms (*"Which one is the cheapest?"*) or calculating pricing.

### CRITICAL DUPLICATION CHECK

Verified across all 8 user turns:
- **1 FINAL STT transcript** generated per utterance.
- **1 Orchestrator turn** processed per utterance.
- **1 LLM decision** made per utterance.
- **1 Final response** generated per utterance.
- **1 TTS audio stream** generated per utterance.
- **Zero** interim transcripts treated as final.
- **Zero** duplicate turn commits by `TurnManager`.
- **Zero** previous assistant responses converted to user input (prevented by frontend microphone gating + backend STT silence during assistant speech).
- **Zero** duplicate WebSocket assistant transcript events.
- **Zero** stale audio replays or uncancelled TTS tasks upon barge-in.

### CHECK SESSION RESET

When a new voice session connects or `clear_conversation` is triggered:
- Active LLM streaming task is cancelled (`self._active_llm_task.cancel()`).
- Active TTS synthesis task is cancelled (`self._active_tts_task.cancel()`).
- Outbound audio pacer buffer is flushed (`await self.pacer.flush()`).
- `TurnManager` state is reset to `TurnState.LISTENING` with cleared turn IDs and timestamps (`self.turn_manager.reset()`).
- Inbound audio energy gate is reset (`self.energy_gate.reset()`).
- Transcripts and message history in `SessionState` are cleared, while database bookings and RAG vector store remain intact.

### FINAL REPORT

```
ROOT CAUSE:
1. Acoustic feedback: Microphone streamed speaker audio to AssemblyAI STT while assistant was speaking, causing assistant speech to re-enter as subsequent user input.
2. Barge-in state desynchronization: _execute_barge_in did not reset TurnManager state to LISTENING, leaving it stuck in SPEAKING and dropping subsequent user speech as TURN DUPLICATE IGNORED.
3. Overly aggressive word-overlap and substring deduplication dropped valid follow-up utterances (e.g., "Which one is the cheapest?", "Book that one.", "How much is my booking?").
4. Session date assignment overwrote check_in with single check_out date, and date parser lacked spoken number words normalization ("twenty first"), trapping the agent in a loop asking for dates.
5. BrowserOutboundPacer emitted redundant assistant transcript events per sentence chunk over WebSocket.
6. Availability tool lacked static catalog fallback when PostgreSQL was disconnected.

BROKEN FILE:
1. frontend/src/services/browserVoice.js & app/telephony/browser_websocket.py
2. app/orchestrator/orchestrator.py
3. app/orchestrator/turn_manager.py
4. app/orchestrator/session.py & app/utils/date_parser.py
5. app/telephony/browser_websocket.py
6. app/tools/availability.py & app/tools/booking.py

BROKEN FUNCTION:
1. BrowserVoiceManager._setupMicrophoneAudio & browser_voice_ws audio loop
2. VoiceAgentOrchestrator._execute_barge_in
3. TurnManager.handle_user_speech_final
4. SessionState.update_context_from_utterance & parse_date_range
5. BrowserOutboundPacer._pacing_loop
6. check_availability & create_booking

WHY IT HAPPENS:
- Without echo gating, speaker audio bled into the mic and transcribed the assistant's own voice.
- Failing to reset TurnManager state to LISTENING upon barge-in blocked all future turns.
- Dropping utterances with >=70% word overlap discarded legitimate follow-up queries.
- Single date responses overwrote check-in instead of setting check-out.
- Outbound pacer broadcasted an assistant transcript event on each individual sentence chunk.
- Database connection refusal left available room lists empty during inquiries.

FIX APPLIED:
1. Added microphone echo suppression in browserVoice.js and gated backend STT audio streaming while assistant is speaking.
2. Ensured _execute_barge_in resets TurnManager to TurnState.LISTENING and resets last_committed_time.
3. Removed broad substring/overlap drops in handle_user_speech_final; added auto-barge-in transition when speech arrives while SPEAKING.
4. Corrected session date assignment so follow-up dates populate check_out; added spoken number word normalization to parse_date_range.
5. Removed redundant per-chunk transcript broadcast from BrowserOutboundPacer._pacing_loop.
6. Added RESORT_ROOMS and HOLD_TOKENS_STORE fallbacks to check_availability and create_booking when PostgreSQL is offline.
```
